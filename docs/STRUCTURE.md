# Repo structure

A navigation map, not a tutorial: what lives where, and the rules that keep it that way. For the
reasoning behind these choices, see `docs/superpowers/specs/2026-07-27-project-structure-design.md`
(design) and `ROADMAP.md` decisions D13–D22 (decision log).

`gen-icons.js`), `docs/` (this file, the design spec, the implementation plan), `schema.sql`
(optional D1 stats table), `wrangler.toml`, `package.json`.

## Engine layers (`app/js/core/engine/`)

Split from the old 514-line `engine.js`. Strictly acyclic — each layer may import only from layers
above it.

| Layer | Module | Contents |
|---|---|---|
| L0 | `constants.js` | `SUITS RANKS NUM_PLAYERS MIN_BID MAX_BID BID_STEP TOTAL_POINTS TARGET_GAMES MAX_REDEALS` |
| L1 | `random.js` | `randomInt` (CSPRNG), `shuffle`, `shuffleFast` |
| L1 | `cards.js` | `buildDeck sameCard rankLabel cardStr sortHand beats winningIndex` |
| L1 | `log.js` | `logG`, `name` |
| L2 | `scoring.js` | `cardPoints trickPoints sideOf defenders` |
| L3 | `match.js` | `createMatch startMatch nextDeal deal endRound publicView` |
| L4 | `bidding.js` | `findBidActor minNextBid bidIsLegal applyBid advanceBidding forceBid finalizeDeclarer` and `redeal` |
| L4 | `contract.js` | `applyTrump callableCards callIsLegal applyCall beginPlay` |
| L4 | `play.js` | `legalCards playIsLegal applyPlay advanceTrick` (`resolveTrick` is module-private) |
| L5 | `ai/heuristic.js` | `aiBidEstimate aiBidDecision aiPickTrump aiPickPartner chooseAICard` |
| L5 | `ai/pimc.js` | `cardKey determinize rolloutClone playOutRound choosePIMCCard PIMC_PLAY_BUDGET` |
| L6 | `flow.js` | `requiredActor` |
| L7 | `ai/index.js` | `aiActionFor` (imports `flow.js` and both AI modules) |
| L8 | `index.js` | barrel — re-exports the public surface, 36 names |

`redeal` sits in `bidding.js` rather than with match lifecycle, and `requiredActor` / `aiActionFor` sit
in their own top dispatch layer above everything else — both relocations exist solely to keep the
graph acyclic (each would otherwise need to import something that imports it back). See the design
spec for the detailed argument.

The room core (`src/core/room/`) has the same shape at smaller scale: leaf modules `constants.js
ids.js seats.js timers.js drive.js membership.js handlers.js view.js` behind one barrel `index.js`
exporting 18 names (550-line `room.js`, split the same way).

## Rules

1. **Consumers import the barrel, never a leaf module.** `src/core/room/`, `app/js/solo.js`, and the
   tests all write `import * as E from ".../core/engine/index.js"` (same pattern for
   `src/core/room/index.js`). **Modules *inside* a subsystem import leaves directly** —
   `bidding.js` importing from `match.js` is fine; the barrel importing back into the subsystem it
   re-exports would create a cycle.
2. **The engine lives under `app/`, not `src/`, because the browser has to fetch it.** Without a
   bundler, anything the browser imports must be reachable over HTTP, and `app/` is the only directory
   Cloudflare's `[assets]` block (and the node server's static handler in `src/server/http.js`) serves.
   One copy on disk means drift is structurally impossible — the same file is what `app/js/solo.js`
   imports, too.
   **`src/core/room/` is the mirror-image rule**: it holds all four players' hands and the host/kick/
   chat state, and must never be reachable by a client, so it deliberately stays out of `app/` even
   though it is just as "core" as the engine.
3. **Client module imports are relative; imports written inside an HTML file are absolute `/js/...`.**
   A relative specifier resolves against the *importing file's* URL: `./session.js` written inside
   `app/js/main.js` resolves correctly, but the same text inside `app/index.html` would resolve to
   `/session.js` and 404 — an HTML document has no "current module" to be relative to, only the page's
   own URL. `test/client-modules.test.js` enforces the relative-only rule for every file under
   `app/js/` by loading each one as a real module and rejecting any import specifier that starts with
   `/`.
4. **Run `npm run build:assets` after touching anything under `app/`.** It walks `app/` to regenerate
   `app/sw.js`'s precache list and cache-busting `VERSION`. `npm run build:assets -- --check` (which
   `test/pwa.test.js` calls) fails the suite if you forget.
5. **A client module may not touch `document`, `window`, `navigator` or `localStorage` at module top
   level — only from inside a function.** `test/client-modules.test.js` `import()`s every file under
   `app/js/` under plain Node, with no DOM, so a top-level reference throws immediately and fails the
   whole suite (confusingly — the stack trace points at the test, not at the module that did it). An
   entry point that must run something on load still can: guard the call behind a `typeof` check rather
   than a direct reference, so the check itself doesn't throw where the global is never declared.
   `app/js/main.js` is the worked example: `if (typeof document !== "undefined") boot();`.
6. **A renderer under `app/js/ui/` takes the view as its first argument and never imports
   `session.js` or `net.js`.** Both pages paint the same table from one implementation, and solo has
   no session — a renderer that reads `S` or calls `send()` is a renderer solo has to fork, which is
   what the old `solo.js` was: a second copy of the seats, the medallion, the scoreboard and the
   action bar. Actions arrive instead as a handler object (`{ bid, pass, trump, call, play, ready,
   nextDeal }`) built by `screens/game.js` (each one a `send()`) or by `solo.js` (each one an engine
   call plus a repaint). `screens/` and `main.js` are the only client files that know a socket exists.

## Entry points

| Command | Runs |
|---|---|
| `npm start` | `src/server/index.js` — node + `ws` |
| `npm run dev` (`npx wrangler dev`) | `src/worker/index.js` — Cloudflare Worker + Durable Object, per `wrangler.toml`'s `main` |
| `npm test` | `node --test` — bare, **no path argument** (a path argument fails on Node 24) |
| `npm run build:assets` | `scripts/build-assets.js` |
